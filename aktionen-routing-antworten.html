    2. Aktionen, Routing, Antworten

    Dieses Kapitel untersucht den Weg einer Anfrage vom Browser bis zu der Aktion, die sie verarbeitet, sowie die Antwort, die diese Aktion zurückgibt. Views werden erst in Kapitel 4 eingeführt: Hier geben die Aktionen direkt Text oder JSON zurück.

from flask import Flask

# die Anwendung: ein Objekt der Klasse Flask. __name__ (hier "__main__" oder "app")
# teilt Flask mit, wo sich die Anwendung befindet, damit es dort nach seinen Dateien suchen kann
app = Flask(__name__)


# eine Action (Flask spricht von einer "View"): die Funktion, die für die Anfrage GET / aufgerufen wird
@app.get("/")
def index():
    # der von der Funktion zurückgegebene Wert IST die an den Browser gesendete Antwort
    return "Hello from Flask!"


# wird nur ausgeführt, wenn die Datei selbst gestartet wird: python app.py
if __name__ == "__main__":
    # der Entwicklungsserver: http://localhost:5000; Strg-C beendet ihn.
    # debug=True: automatisches Neuladen nach einer Änderung und eine Debugging-
    # Seite im Fehlerfall (NIEMALS in der Produktion)
    app.run(port=5000, debug=True)

    Gehen wir diesen Code Schritt für Schritt durch:

    • Zeile 2: importiert die Klasse [Flask] aus dem Paket [flask], das von [pip] in der virtuellen Umgebung installiert wurde. In [Python] ist eine Datei mit der Endung [.py] ein Modul, und ein Modul verwendet nur die Namen, die es selbst importiert oder definiert hat (abgesehen von den eingebauten Funktionen der Sprache, etwa [print] oder [len]);
    • Zeile 6: die Anwendung, ein Objekt der Klasse [Flask]. Sie empfängt die Anfragen und wählt die Funktion aus, die jede davon verarbeitet. Der Parameter ist der Name des aktuellen Moduls, den [Python] in der Variablen [__name__] ablegt: [Flask] nutzt ihn, um den Anwendungsordner zu finden, in dem es später die Views (Ordner [templates]) und die statischen Dateien (Ordner [static]) sucht;
    • Zeile 10: [@app.get("/")] ist ein Dekorator. Ein Dekorator wird als [@expression] unmittelbar vor der Definition einer Funktion (oder einer Klasse) geschrieben; [Python] ruft den Ausdruck mit der Funktion als Parameter auf, wenn es die Definition ausführt. Hier registriert [app.get("/")] die Funktion [index] in der Anwendung: Sie verarbeitet Anfragen für [GET /]. Das ist das Routing. Eine Funktion, die auf diese Weise mit einer Route verknüpft ist, ist eine Aktion (die Dokumentation von [Flask] bezeichnet sie als View-Funktion; siehe die Einführung);
    • Zeilen 11–13: Die Aktion gibt eine Zeichenkette zurück. Der von einer Aktion zurückgegebene Wert ist die an den Browser gesendete Antwort: [Flask] legt ihn in den Rumpf der HTTP-Antwort. Nach Konvention werden Funktionsnamen ([Python]) in Kleinbuchstaben geschrieben, wobei die Wörter durch Unterstriche getrennt werden ([action01_post]);
    • Zeile 17: Wenn die Datei selbst ausgeführt wird ([python app.py]), [Python] weist der Variablen [__name__] den Wert ["__main__"] zu; wird das Modul von einem anderen Modul importiert, ist sie auf den Namen des Moduls gesetzt (["app"]). Dieser in [Python] sehr verbreitete Test reserviert den restlichen Code also für den Fall, dass die Datei direkt gestartet wird;
    • Zeile 21: [app.run] startet den [Werkzeug] -Entwicklungsserver, der auf Port 5000 des Rechners auf Anfragen lauscht (5000 ist der Standardwert), bis er mit [Ctrl-C] gestoppt wird. [debug=True] aktiviert den Debug-Modus: Der Server überwacht die Dateien der Anwendung und startet sie neu, sobald eine davon geändert wird; eine nicht behandelte Ausnahme zeigt eine Debug-Seite an (siehe Beispiel 03). Dieser Modus ist für die Entwicklung gedacht, und nur dafür: Die Debug-Seite erlaubt es, [Python]-Code auf dem Server auszuführen.

    # app.py: die Anwendung, von einer "Factory" erstellt
from flask import Flask

from controllers.home import home
from controllers.first import first


# die Factory: eine Funktion, die die Anwendung erstellt und konfiguriert
def create_app():
    app = Flask(__name__)
    # jeder Blueprint (eine Gruppe von Routen) wird bei der Anwendung registriert
    app.register_blueprint(home)
    app.register_blueprint(first)
    return app


if __name__ == "__main__":
    create_app().run(port=5000, debug=True)
    • Zeilen 4–5: Importieren die beiden Blueprints, die Objekte [home] und [first], aus den Modulen [controllers/home.py] und [controllers/first.py];
    • Zeilen 9–14: Die Anwendung ist keine beim Import erzeugte Modulvariable mehr; sie wird von einer Funktion erstellt, die man als *Factory* bezeichnet. Dies ist der in der [Flask]-Dokumentation empfohlene Ansatz, dem alle folgenden Beispiele folgen: Die Konfiguration der Anwendung ist an einer einzigen Stelle gebündelt, und es lassen sich mehrere Anwendungen mit unterschiedlichen Konfigurationen erstellen (zum Beispiel für Tests). Der Befehl [flask --app app run] erkennt dies: Fehlt eine Variable [app], ruft er die Funktion [create_app] des Moduls auf;
    • Zeilen 12–13: Jeder Blueprint wird in der Anwendung registriert ; seine Routen werden zu Routen der Anwendung;
    • Zeile 18: Die Anwendung wird erstellt, dann wird der Server gestartet.

    # controllers/first.py: ein Blueprint, dessen Routen alle mit /first beginnen
from flask import Blueprint

# url_prefix: Präfix, das alle Routen des Blueprints gemeinsam haben
first = Blueprint("first", __name__, url_prefix="/first")


# GET /first: die Route "" bezeichnet das Präfix selbst
@first.get("")
def index():
    return "Action [index] of the [first] blueprint"


# GET /first/action01
@first.get("/action01")
def action01():
    return "Action [action01] of the [first] blueprint, GET request"


# POST /first/action01: gleicher Pfad, andere HTTP-Methode, andere Funktion
@first.post("/action01")
def action01_post():
    return "Action [action01_post] of the [first] blueprint, POST request"


# GET /first/products/17: <int:id> ist eine Pfadvariable;
# der Konverter [int] akzeptiert nur Ziffern und liefert eine Ganzzahl
@first.get("/products/<int:id>")
def product(id):
    return f"Product no. {id}"


# GET /first/products/17/reviews/3: zwei Pfadvariablen
@first.get("/products/<int:id>/reviews/<int:number>")
def review(id, number):
    return f"Review no. {number} of product no. {id}"


# GET /first/files/...: der Konverter [path] akzeptiert jedes Pfadende,
# einschließlich Schrägstrichen
@first.get("/files/<path:path>")
def file(path):
    return f"Requested file: {path}"

    Gehen wir diesen Code Schritt für Schritt durch:

    • Zeile 5: Der Parameter [url_prefix] legt das allen Routen des Blueprints gemeinsame Präfix fest: Seine Aktionen verarbeiten URL-Routen, die mit [/first] beginnen;
    • Zeilen 9–10: Die Route [""] bezeichnet das Präfix selbst: Die Aktion [index] verarbeitet [GET /first]. Die URL einer Aktion ist die Verkettung des Präfixes des Blueprints und des Pfads ihrer Route. Der Name der Aktion ([index]) kann in einem anderen Blueprint derselbe sein: [Flask] unterscheidet sie anhand des Blueprint-Namens ([first.index], [home.index]);
    • Zeilen 15–16: Die Aktion [action01] verarbeitet [GET /first/action01];
    • Zeilen 21–22: derselbe Pfad, aber für die Methode POST: Der Dekorator [post] ersetzt [get]. Es gibt außerdem [put], [delete] und [patch] sowie den allgemeinen Dekorator [route], der eine Liste von Methoden akzeptiert: [@first.route("/action01", methods=["GET", "POST"])]. Innerhalb desselben Moduls dürfen zwei Funktionen nicht denselben Namen haben (die zweite würde die erste ersetzen): daher der Name [action01_post];
    • Zeilen 28–30: [<int:id>] ist eine Pfadvariable: Dieses URL-Segment kann mehrere Werte annehmen. [int] ist ein Konverter: Das Segment muss aus Ziffern bestehen, andernfalls passt die Route nicht; sein Wert wird in eine Ganzzahl umgewandelt und dann an den gleichnamigen Parameter der Aktion übergeben, [id]. Für [/first/products/17] ist [id] gleich der Zahl 17. Das ist Data-Binding (*data binding*), das das nächste Kapitel ausführlich behandelt. Ohne Konverter ([<id>]) akzeptiert die Variable jeden Text ohne Schrägstrich und bleibt eine Zeichenkette. [Werkzeug] stellt außerdem die Konverter [float], [uuid] und [path] bereit, und Beispiel 12 zeigt, wie man eigene schreibt;
    • Zeile 30: ein f-String (das Präfix [f]): Jeder Ausdruck in geschweiften Klammern wird ausgewertet, und sein Wert wird in den Text eingefügt;
    • Zeilen 34–36: zwei Pfadvariablen, die als zwei Parameter an die Aktion übergeben werden;
    • Zeilen 41–43: Der Konverter [path] akzeptiert jedes URL-Ende, einschließlich [/].

import asyncio
import time
from dataclasses import dataclass

from flask import Blueprint, Response, abort, jsonify

responses = Blueprint("responses", __name__, url_prefix="/responses")


# ein String, als reiner Text angekündigt: der Browser zeigt ihn unverändert an.
# Response: die vollständige Antwort, von der Action selbst erstellt
@responses.get("/text")
def text():
    return Response("<h1>Action [text]</h1>", mimetype="text/plain")


# ein einzelner String: Flask sendet ihn mit dem Typ text/html; der Browser interpretiert ihn
@responses.get("/html")
def html():
    return "<h1>Action [html]</h1>"


# eine Dataclass: eine Datenklasse (siehe Beispiel 06), hier im Modul deklariert
@dataclass
class Person:
    last_name: str
    first_name: str
    age: int


# ein Objekt: jsonify serialisiert es zu JSON, mit dem Typ [application/json]
@responses.get("/json")
def json():
    return jsonify(Person("Martin", "Jean", 42))


# ein unverändert zurückgegebenes Dictionary: Flask serialisiert es selbst zu JSON
@responses.get("/dictionary")
def dictionary():
    return {"last_name": "Martin", "first_name": "Jean", "age": 42}


# eine Liste: wird zu einem JSON-Array serialisiert
@responses.get("/list")
def list():
    return ["Mme", "Melle", "Mr"]


# ein Tupel (Inhalt, Code): der Code 201 (Created) statt 200 (OK)
@responses.get("/created")
def created():
    return {"message": "resource created"}, 201


# keine Antwort: der Code 204 (No Content) bedeutet "nichts anzuzeigen"
@responses.get("/empty")
def empty():
    return "", 204


# eine asynchrone Action (async def): Flask wartet auf das Ende der Coroutine.
# Sie benötigt das Extra [async] von Flask: pip install "flask[async]"
@responses.get("/task")
async def task():
    start = time.perf_counter()
    await asyncio.sleep(0.5)  # 500 ms warten, ohne die Ereignisschleife zu blockieren
    return {"wait": f"{round((time.perf_counter() - start) * 1000)} ms"}


# ein "erwarteter" Fehler: das Tupel (Inhalt, 404) erzeugt eine 404-Antwort
@responses.get("/not-found")
def not_found():
    return {"message": "This resource does not exist"}, 404


# dasselbe mit abort: eine HTTP-Exception, die Flask in eine 404-Antwort umwandelt
@responses.get("/abort")
def abort_action():
    abort(404, "This resource does not exist either")


# ein "unerwarteter" Fehler: eine unbehandelte Exception erzeugt eine 500-Antwort
@responses.get("/exception")
def exception():
    raise RuntimeError("An unexpected error")

    • Zeilen 13–15: Die Klasse [Response] stellt eine vollständige HTTP-Antwort dar. Die Aktion erstellt sie selbst: den Rumpf und den Typ ([mimetype]), hier [text/plain] (reiner Text). Der Browser interpretiert die Tags nicht;
    • Zeilen 19–21: dieselbe Zeichenkette, für sich allein zurückgegeben: [Flask] sendet sie mit dem Typ [text/html], und der Browser interpretiert sie;
    • Zeilen 25–29: eine Dataclass – eine Klasse, in der nur die Felder und ihre Typen deklariert werden; der Dekorator [@dataclass] schreibt den Konstruktor ([Person("Martin", "Jean", 42)]), die Textdarstellung und den Objektvergleich selbst. Beispiel 06 greift dies wieder auf;
    • Zeilen 33–35: Die Funktion [jsonify] wandelt ihren Parameter in JSON um und erzeugt eine Antwort vom Typ [application/json]. Der JSON-Provider von [Flask] kann Dictionaries, Listen, Zeichenketten, Zahlen, Boolesche Werte, [None] (wird zu [null]) sowie Dataclasses, Datumsangaben und [Decimal] -Zahlen umwandeln (siehe Beispiel 06);
    • Zeilen 39–41: noch einfacher: Eine Aktion, die ein Dictionary (oder eine Liste, Zeilen 45–47) zurückgibt, erzeugt eine JSON-Antwort, ohne [jsonify] aufzurufen. Eine Dataclass dagegen muss über [jsonify] laufen: Würde sie für sich allein zurückgegeben, führte das zu einem Fehler („The view function did not return a valid response“);
    • Zeilen 51–53: Eine Aktion kann ein Tupel [(content, code)] zurückgeben: Der Statuscode 201 ([Created]) ersetzt den Statuscode 200. Ein Tupel kann auch Header enthalten: [(content, code, {"X-Example": "03"})];
    • Zeilen 57–59: Der Code 204 ([No Content]) bedeutet „nichts anzuzeigen“: Die Antwort hat keinen Rumpf;
    • Zeilen 64–68: eine asynchrone Aktion, deklariert mit [async def]. Das Schlüsselwort [await] setzt die Coroutine während des Wartens aus ([asyncio.sleep]), ohne das Programm zu blockieren. [Flask] führt die Aktion in einer für die Anfrage erzeugten Ereignisschleife aus und wartet auf ihr Ergebnis: Das ist nützlich, um mehrere Wartevorgänge parallel zu starten (zum Beispiel mehrere Aufrufe von Webservices), macht aber [Flask] selbst nicht asynchron. Sie müssen die Erweiterung [[async]] von [Flask] installieren (siehe [requirements.txt]);
    • Zeilen 72–74: ein „erwarteter“ Fehler: Das Tupel [(content, 404)] gibt eine 404-Antwort zurück ([Not Found]) mit einem von der Aktion gewählten Rumpf (JSON);
    • Zeilen 78–80: derselbe Fehler, erzeugt durch die Funktion [abort]. [abort] gibt nichts zurück: Sie löst eine Ausnahme aus ([NotFound], für den Code 404), die die Aktion beendet; [Flask] wandelt sie in eine Fehlerantwort um, mit der als zweitem Parameter übergebenen Meldung. Dies ist die üblichste Art, eine Aktion wegen eines Fehlers zu beenden, selbst tief in einer von der Aktion aufgerufenen Funktion;
    • Zeilen 84–86: ein „unerwarteter“ Fehler – eine Ausnahme, die niemand behandelt – erzeugt eine 500-Antwort ([Internal Server Error]).

from flask import Blueprint, redirect, url_for

redirects = Blueprint("redirects", __name__)


# permanente Weiterleitung (301): die Seite hat dauerhaft eine neue Adresse
@redirects.get("/old")
def old_page():
    return redirect("/new", code=301)


@redirects.get("/new")
def new_page():
    return "You are on the [new] page"


# temporäre Weiterleitung (302, der Standardcode) auf eine berechnete Adresse,
# die durch Aneinanderhängen von Textstücken entsteht
@redirects.get("/go/<destination>")
def go(destination):
    return redirect("/page/" + destination)


# url_for erstellt die Adresse einer ACTION, die über ihren Namen bezeichnet wird
# ("blueprint.function"): der Parameter [name] wird für eine URL korrekt kodiert
@redirects.get("/to-template/<destination>")
def to_template(destination):
    return redirect(url_for("redirects.page", name=destination))


@redirects.get("/page/<name>")
def page(name):
    return f"You are on the [{name}] page"


# Weiterleitung auf eine andere Website
@redirects.get("/documentation")
def documentation():
    return redirect("https://flask.palletsprojects.com/")

import time

from flask import Blueprint, Response, make_response, request

http = Blueprint("http", __name__, url_prefix="/http")


# die Anfrage: Methode, Pfad, Parameter, Header ...
# [request] ist ein globales Flask-Objekt, das die AKTUELLE Anfrage bezeichnet
@http.get("/request")
def request_info():
    # ein Python-Dictionary behält die Einfügereihenfolge seiner Schlüssel bei
    return {
        "method": request.method,
        "path": request.path,
        # query_string: Bytes, die wir in Text dekodieren
        "parameters": request.query_string.decode(),
        "browser": request.headers.get("User-Agent"),
        "ip": request.remote_addr,
    }


# die Antwort: make_response erstellt das Antwortobjekt aus dem, was die
# Action zurückgeben würde; wir fügen ihm einen Header hinzu, bevor wir es zurückgeben
@http.get("/header")
def header():
    response = make_response("Response with an added header")
    response.headers["X-Example"] = "05-request-response"
    return response


# die "von Hand" erstellte Antwort: Rumpf, Code, Typ
@http.get("/response")
def response():
    return Response("Response built by [Response(...)]", status=200,
                    mimetype="text/plain")


# eine Antwort, die in TEILEN gesendet wird: der Code und die Header gehen mit dem
# ersten Teil hinaus und können danach nicht mehr geändert werden
@http.get("/stream")
def stream():
    def chunks():
        yield "Start of the response... "
        time.sleep(1)
        # zu spät, um einen Fehler anzukündigen: der Code 200 ist bereits gesendet
        raise RuntimeError("error in the middle of the response")

    return Response(chunks(), mimetype="text/plain")
    • Zeile 4: Import des Objekts [request]. In [Flask] ist die aktuelle Anfrage kein Parameter der Aktion: Sie ist ein globales Objekt, [request], das aus dem Paket [flask] importiert wird. Wie kann sich ein globales Objekt auf die aktuelle Anfrage beziehen, wenn der Server mehrere Anfragen gleichzeitig in mehreren Threads (parallelen Ausführungssträngen) verarbeitet? [request] fungiert als Proxy: Bei jeder Verwendung leitet es die Operation an die Anfrage im aktuellen Thread weiter. [Flask] bezeichnet dies als den Request-Kontext: Während eine Anfrage verarbeitet wird, bezieht sich [request] auf genau diese Anfrage. Außerhalb der Anfrageverarbeitung führt seine Verwendung zu einem Fehler („Working outside of request context“);
    • Zeilen 14–20: einige Eigenschaften der Anfrage: ihre HTTP-Methode, ihr Pfad, ihre rohen Parameter (der Teil der URL nach [?], in Byte-Form, den [decode] in Text umwandelt), ihre Header ([request.headers], ein Dictionary, dessen Methode [get] für einen fehlenden Header [None] zurückgibt), die IP-Adresse des Clients. Die Parameter werden im nächsten Kapitel einzeln behandelt;
    • Zeilen 26–30: Die Funktion [make_response] erstellt das Antwortobjekt (eine [Response]) auf Grundlage dessen, was die Aktion zurückgeben würde (hier eine Zeichenkette); die Aktion kann es dann ändern, bevor sie es zurückgibt. Es wird ein Header [X-Example] hinzugefügt (nach Konvention beginnen anwendungsspezifische Header oft mit [X-]);
    • Zeilen 34–37: die „von Hand gebaute“ Antwort: der Rumpf, der Statuscode und der Typ;
    • Zeilen 42–50: eine Antwort, die in Teilen gesendet wird (*Streaming*). Die Funktion [chunks] ist ein Generator: Jedes [yield] erzeugt ein Teilstück des Rumpfs. Da die Antwort mit einem Generator aufgebaut wird, ist ihre Länge nicht im Voraus bekannt: Der Server sendet den Statuscode und die Header und dann jedes Teilstück, sobald es erzeugt ist. Das ist nützlich für eine sehr lange Antwort, die stückweise erzeugt wird. Sobald aber das erste Teilstück gesendet wurde, kann sich der Statuscode nicht mehr ändern: Hier löst der Generator nach dem ersten Teilstück eine Ausnahme aus. Das ist der Fehler, den es zu vermeiden gilt: Eine bereits begonnene Antwort kann nicht mehr zu einer Fehlerantwort werden.

    # products/service.py: der VERTRAG des Service, was er kann, ohne zu sagen, wie
from abc import ABC, abstractmethod

from flask import current_app

from products.product import Product


# eine abstrakte Klasse (ABC): aus ihr kann kein Objekt erzeugt werden; eine Kindklasse
# muss alle mit @abstractmethod markierten Methoden schreiben (überschreiben)
class ProductsService(ABC):

    @abstractmethod
    def find_all(self) -> list[Product]: ...

    # Product | None: ein Produkt oder None, wenn es nicht existiert
    @abstractmethod
    def find_by_id(self, id: int) -> Product | None: ...


# der Service der aktuellen Anwendung (siehe app.py). current_app bezeichnet
# die Anwendung, die die aktuelle Anfrage bearbeitet
def products_service() -> ProductsService:
    return current_app.extensions["products_service"]
    • Zeilen 11–18: der Vertrag des Services – was er kann, ohne festzulegen, wie. In [Python] wird ein Vertrag durch eine abstrakte Klasse definiert: eine Klasse, die von [ABC] erbt ([Abstract Base Class]) und deren mit [@abstractmethod] markierte Methoden keinen Rumpf haben (die drei Punkte [...] dienen als leerer Rumpf). Von dieser Klasse kann man kein Objekt erzeugen; eine Unterklasse muss alle ihre abstrakten Methoden überschreiben. Das entspricht den Interfaces von [Java] und [C#];
    • Zeile 14: die Annotation für den von der Methode zurückgegebenen Typ (nach [->]): eine Liste von Produkten. [self] ist das Objekt, auf dem die Methode aufgerufen wird (das Äquivalent von [this] in [Java]), stets als erster Parameter aufgeführt;
    • Zeile 18: [Product | None]: ein Produkt oder [None] , wenn es nicht existiert;
    • Zeilen 23–24: Die Funktion, die den Service bereitstellt für die Aktionen. [current_app] ist, wie [request], ein Proxy: Er bezieht sich auf die Anwendung, die die aktuelle Anfrage verarbeitet. [app.extensions] ist ein Dictionary, das [Flask] den Erweiterungen (den Bibliotheken, die zu [Flask] hinzugefügt werden) zur Verfügung stellt, damit sie dort ihre Objekte ablegen können; wir verwenden es für unsere eigenen Services. Die Funktion gibt außerdem den Typ des Services an ([-> ProductsService]): [Visual Studio Code] kann dann seine Methoden vorschlagen.

    # products/in_memory_service.py: eine IMPLEMENTIERUNG des Vertrags, mit Daten im Speicher
from decimal import Decimal

from products.product import Product
from products.service import ProductsService


class InMemoryProductsService(ProductsService):

    def __init__(self):
        # ein Tupel: eine Liste, die nicht geändert werden kann
        self._products = (
            Product(1, "pen", Decimal("1.5")),
            Product(2, "notebook", Decimal("3.2")),
            Product(3, "eraser", Decimal("0.8")),
        )

    def find_all(self) -> list[Product]:
        return list(self._products)

    def find_by_id(self, id: int) -> Product | None:
        # next(generator, None): das erste passende Produkt oder None
        return next((p for p in self._products if p.id == id), None)
    • Zeile 8: Die Klasse erbt den Vertrag und definiert seine beiden Methoden neu;
    • Zeilen 10–15: [__init__] ist der Konstruktor der Klasse. Er speichert die Produkte im Attribut [_products] des Objekts; der führende Unterstrich kennzeichnet nach Konvention ein privates Attribut, das Code außerhalb der Klasse nicht verwenden soll. Die Produkte liegen in einem Tupel (in runden Klammern): einer unveränderlichen Sequenz. Der Preis wird aus einer Zeichenkette konstruiert ([Decimal("1.5")]): Aus dem [float] 1.5 erzeugt, würde er dessen Ungenauigkeiten erben;
    • Zeilen 18–19: Die Methode gibt eine neue Liste zurück, eine Kopie des Tupels: Der Aufrufer kann sie ändern, ohne die Daten des Services zu beeinflussen;
    • Zeilen 21–23: [(p for p in self._products if p.id == id)] ist ein Generatorausdruck: Er erzeugt nacheinander die Produkte, deren ID mit der angeforderten übereinstimmt. [next] gibt das erste Produktelement zurück oder, falls es keines gibt, den Standardwert [None].

from flask import Blueprint, jsonify

from products.service import products_service

products = Blueprint("products", __name__, url_prefix="/products")


@products.get("")
def list_all():
    # der Service wird bei jeder Anfrage von der Anwendung geholt
    return jsonify(products_service().find_all())


@products.get("/<int:id>")
def one_product(id):
    product = products_service().find_by_id(id)
    if product is None:
        return {"message": f"Product no. {id} not found"}, 404
    return jsonify(product)
    • Zeile 4: Der Blueprint kennt nur den Vertrag des Services (das Modul [service]), nicht seine Implementierung: Er weiß nicht, dass die Produkte im Speicher liegen;
    • Zeilen 10–12: Die Aktion fordert den Service von der Anwendung an und delegiert dann die Arbeit an ihn. [jsonify] wandelt die Liste der Dataclasses in ein JSON-Array um;
    • Zeilen 16–20: Ein unbekanntes Produkt liefert eine 404-Antwort mit einer Meldung in JSON.

    # clients/controller.py: ein zweiter Blueprint, der DENSELBEN Service verwendet
from dataclasses import dataclass
from decimal import Decimal

from flask import Blueprint, jsonify

from products.service import products_service

clients = Blueprint("clients", __name__, url_prefix="/clients")


# der Inhalt des Warenkorbs, als JSON zurückgegeben
@dataclass
class Cart:
    client: str
    items: int
    total: Decimal


@clients.get("/cart")
def cart():
    products = products_service().find_all()
    # die Summe der Preise; start=Decimal(0): wir addieren Decimal-Werte
    total = sum((p.price for p in products), start=Decimal(0))
    return jsonify(Cart("Jean Martin", len(products), total))
    • Zeilen 14–17: der Inhalt des Warenkorbs, als JSON ausgegeben;
    • Zeile 22: Dieser Blueprint verwendet denselben Service wie der Produkt-Blueprint: ein einziges, gemeinsames Objekt;
    • Zeile 24: [sum] addiert die Elemente eines iterierbaren Objekts; ihr Parameter [start] ist der Anfangswert der Summe (standardmäßig 0). Mit [Decimal(0)] statt der Ganzzahl 0 zu beginnen, ist nicht unerlässlich (eine Ganzzahl und ein [Decimal] lassen sich addieren), garantiert aber ein Ergebnis vom Typ [Decimal] auch bei einem leeren Warenkorb.

    # app.py: die Anwendung von Beispiel 06
from flask import Flask

from clients.controller import clients
from products.controller import products
from products.in_memory_service import InMemoryProductsService


def create_app():
    app = Flask(__name__)
    # JSON: Akzente beibehalten, Schlüssel in ihrer ursprünglichen Reihenfolge (siehe Beispiel 03)
    app.json.ensure_ascii = False
    app.json.sort_keys = False
    # der SERVICE: ein einziges Objekt, einmal beim Start erstellt und von
    # allen Anfragen gemeinsam genutzt. Wir speichern ihn in app.extensions, einem Dictionary, das
    # Flask den Erweiterungen zur Verfügung stellt ... und unseren Services
    app.extensions["products_service"] = InMemoryProductsService()
    app.register_blueprint(products)
    app.register_blueprint(clients)
    return app


if __name__ == "__main__":
    create_app().run(port=5000, debug=True)
    • Zeile 17: Hier – und nur hier – wird die Implementierung des Services gewählt. Der Service wird einmal beim Start erstellt, und dasselbe Objekt bearbeitet alle Anfragen aller Benutzer: Es ist ein Singleton (der Standard-Scope der [Spring]-Beans). Um auf eine Implementierung umzustellen, die aus einer Datenbank liest, müsste man nur diese Zeile ändern: Die Blueprints, die nur den Vertrag kennen, blieben unverändert. Das ist der Kern der Dependency Injection, auch wenn sie „von Hand“ umgesetzt wird: Jeder Teil der Anwendung hängt von Verträgen ab, und eine einzige Stelle legt die Implementierungen fest.

    Ein von allen Anfragen gemeinsam genutzter Service muss damit umgehen können, gleichzeitig von mehreren Anfragen verwendet zu werden: Der Entwicklungsserver verarbeitet jede Anfrage in einem eigenen Thread. Das ist hier unproblematisch: Er liest lediglich Daten, die sich nie ändern. Beispiel 20 zeigt einen Service, dessen Daten sich ändern, und die dafür nötigen Vorkehrungen.
